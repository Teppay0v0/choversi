# 端末の制約 —— 音と触覚

体感の議論をする前に確かめること。実装したかどうかと、
**プレイヤーの耳と手に届いたかどうか**は別問題である。

## iOS が音を消す

iOS は WebAudio だけの出力を「環境音（ambient）」扱いにするため、
**本体側面の消音スイッチで全SEが丸ごと消える**。
`<audio>` / `<video>` 要素の再生には適用されないため、
「動画は鳴るのにゲームは無音」という状態が起きる。

対策（`Audio_.init` / `Audio_.unmute`）：

1. **AudioSession API**（Safari 16.4+）
   `navigator.audioSession.type = 'playback'` を宣言する。これが本命。
2. **無音トラック**（保険）
   0.05秒の無音WAVを `<audio loop>` で再生し、メディア再生セッションを起こす。
3. どちらも効かない端末では、確認画面に消音スイッチの注意を出す。

参考: [WebKit Bug 237322](https://bugs.webkit.org/show_bug.cgi?id=237322)

## iOS に Vibration API は無い

`navigator.vibrate` は iOS Safari に存在しない（`undefined`）。
Android / Chrome にしか無いAPIであり、**iPhone では触覚が完全に無効**だった。

代替（`Haptic`）：`switch` 属性つきチェックボックスを切り替えると
システムが触覚を返す挙動を借りる（Safari 17.4+）。
`'switch' in document.createElement('input')` で判定できる。

### 制約：ユーザー操作の中でしか鳴らない

この手法は**ユーザー操作の呼び出し階層の中**でしか発火しない。
したがって触覚は2種類に分けて考える。

| | 経路 | iOSで届くか |
|---|---|---|
| 自分の入力（タップ・スワイプ・ガード） | `Input.down` / `emit('SWIPE')` | **確実に届く** |
| 被弾・ガード成立・PERFECT | タイマー駆動 | 端末により届かない |

前者を必ず入れること。「ただクリックしているだけ」という感想の
かなりの部分は、**触れた事実が手に返ってこない**ことに由来する。

強さを持てないため、切替回数で重さを表す（軽1／中2／重3）。
要素は `display:none` にすると発火しない。描画したまま画面外へ逃がす。

## 確認画面

タイトル →「音と振動を確かめる」。
端末・AudioContextの状態・再生セッション宣言・**出力レベルの実測値**・
触覚の方式と発火回数を表示する。

出力レベルは `AnalyserNode` で master を実測しているので、
「鳴らしているつもりで信号が出ていない」事故を切り分けられる。
ただし**ハードウェアの消音スイッチは検出できない**。
最終的な判定は、実機で耳と手で確かめるしかない。
