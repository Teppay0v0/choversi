# 端末の制約 —— 音と触覚

体感の議論をする前に確かめること。実装したかどうかと、
**プレイヤーの耳と手に届いたかどうか**は別問題である。

## iOS が音を消す

iOS は WebAudio だけの出力を「環境音（ambient）」扱いにするため、
**本体側面の消音スイッチで全SEが丸ごと消える**。
`<audio>` / `<video>` 要素の再生には適用されないため、
「動画は鳴るのにゲームは無音」という状態が起きる。

対策（`Audio_.init` / `Audio_.unmute`）：

1. **AudioSession API**（Safari 16.4+）
   `navigator.audioSession.type = 'playback'` を宣言する。これが本命。
2. **無音トラック**（保険）
   0.05秒の無音WAVを `<audio loop>` で再生し、メディア再生セッションを起こす。
3. どちらも効かない端末では、確認画面に消音スイッチの注意を出す。

参考: [WebKit Bug 237322](https://bugs.webkit.org/show_bug.cgi?id=237322)

## iOS に Vibration API は無い

`navigator.vibrate` は iOS Safari に存在しない（`undefined`）。
Android / Chrome にしか無いAPIであり、**iPhone では触覚が完全に無効**だった。

代替（`Haptic`）：`switch` 属性つきチェックボックスを切り替えると
システムが触覚を返す挙動を借りる（Safari 17.4+）。
`'switch' in document.createElement('input')` で判定できる。

### 制約：ユーザー操作の中でしか鳴らない

この手法は**ユーザー操作の呼び出し階層の中**でしか発火しない。
したがって触覚は2種類に分けて考える。

| | 経路 | iOSで届くか |
|---|---|---|
| 自分の入力（タップ・スワイプ・ガード） | `Input.down` / `emit('SWIPE')` | **確実に届く** |
| 被弾・ガード成立・PERFECT | タイマー駆動 | 端末により届かない |

前者を必ず入れること。「ただクリックしているだけ」という感想の
かなりの部分は、**触れた事実が手に返ってこない**ことに由来する。

強さを持てないため、切替回数で重さを表す（軽1／中2／重3）。
要素は `display:none` にすると発火しない。描画したまま画面外へ逃がす。

## 確認画面

タイトル →「音と振動を確かめる」。
端末・AudioContextの状態・再生セッション宣言・**出力レベルの実測値**・
触覚の方式と発火回数を表示する。

出力レベルは `AnalyserNode` で master を実測しているので、
「鳴らしているつもりで信号が出ていない」事故を切り分けられる。
ただし**ハードウェアの消音スイッチは検出できない**。
最終的な判定は、実機で耳と手で確かめるしかない。

# 保留：ネイティブアプリでの触覚

Web の `navigator.vibrate` は **on/off とミリ秒しか指定できない**。
iOS では上記の代替（スイッチ触覚）も実機で発火しなかった。
**これは Web の制約であって、製品の制約ではない。**

最終的にアプリとして出すなら、触覚は必ず入れる。むしろ Web より遥かに強い：

| | Web | ネイティブ |
|---|---|---|
| iOS | 手段なし | **Core Haptics**（`CHHapticEngine`） |
| Android | on/off + ms | `VibrationEffect.createWaveform` + `Composition`（API 30+） |

Core Haptics は **intensity（強さ 0–1）** と **sharpness（鋭さ 0–1）** を
持つ transient / continuous イベントを、任意のタイミングで重ねられる。
「打撃の重さ」「ガードの硬さ」「予備動作の気配」を別々の質感で出せる。

## 触覚の設計（ここまでの設計判断を残す）

`Haptic.fire()` の呼び出し地点はすでにコード内に置いてある。
ネイティブ側ではこの表に差し替える。

| 出来事 | 呼び出し | 質感 | intensity / sharpness / 長さ |
|---|---|---|---|
| 指を置く | `haptic('touch')` | 触れた確認。ごく軽い | transient 0.25 / 0.9 / — |
| 拳が溜まる | （未実装） | **continuous で徐々に強くなる**。溜めが手で分かる | continuous 0.1→0.5 / 0.2 / 溜めた時間 |
| 拳を放つ | `haptic('swing')` | 抜ける。溜めた分だけ強い | transient 0.3+0.4·wind / 0.7 / — |
| 相手の予備動作 | （未実装） | **気配**。見える前に感じる。ごく弱い低周波 | continuous 0.15 / 0.05 / tell の長さ |
| 主観時間へ入る | （未実装） | 沈む。世界が遠のく | continuous 0.5→0.1 / 0.1 / 300ms |
| ガードで止めた | `haptic('guard')` | **硬い**。芯で受けた | transient 0.8 / 1.0 → 0.3 / 0.4 の2連 |
| 打撃が入った | `haptic('good')` | 抜けた。鋭い | transient 0.6 / 0.85 |
| PERFECT カウンター | `haptic('perfect')` | **一番強い**。返した手応え | transient 1.0 / 1.0 + continuous 0.6 / 0.2 / 120ms |
| 被弾 | `haptic('hurt')` | 鈍い。重い。尾を引く | transient 0.9 / 0.15 + continuous 0.5→0 / 0.1 / 250ms |
| 心音（HP低下時） | （未実装） | 2連の低周波。画面を見ずに状態が分かる | transient 0.4 / 0.05 ×2, 間隔 170ms |

### 設計の芯

1. **鋭さ（sharpness）で「何が起きたか」を分ける。**
   打撃は鋭く、被弾は鈍い。強弱だけでは区別がつかない。
2. **予備動作と溜めは continuous。** 単発の振動では「気配」も「溜まっていく」も
   表現できない。ここが Web で最も欠けていた部分であり、
   ネイティブにする最大の理由。
3. **見える前に感じる。** 予備動作の触覚は視覚より先に出す。
   「見えた瞬間、世界は遅くなる」の一歩手前に「感じた」を置く。

### 移植時にやること

- `Haptic.fire(pat)` の中身をブリッジ呼び出しに差し替える（呼び出し地点は変えない）
- `p.wind` の進行を毎フレーム触覚へ流す経路を足す（continuous）
- `startEnemyAttack` の tell 開始と `Clock.to()` のスロー突入に触覚を足す
- 設定に触覚の強さ（切／弱／標準）を置く。切っても遊べること
