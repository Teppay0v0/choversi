# MAAi -間合- / Web プレイアブル試作 v0.1

> 見えた瞬間、世界は遅くなる。 — *When you see it, time slows.*

`PROTOTYPE_SPEC_v0.2` の**体験の核**を、iPhone の Safari で今すぐ触れる形にした試作です。
Unity 着手前に「予備動作を読む → 主観時間 → 腕が追従する → 拍へ着地する」が
本当に気持ちいいかを検証することだけを目的にしています。

---

## 動かし方

ビルド不要。`maai/index.html` 1 ファイルで完結します。

| 方法 | 手順 |
|---|---|
| **iPhone 実機（推奨）** | AirDrop / iCloud Drive で `index.html` を iPhone へ送り、Safari で開く |
| ローカルサーバー | `cd maai && python3 -m http.server 8000` → 同一 Wi-Fi の iPhone から `http://<MacのIP>:8000/` |
| Mac で確認 | `index.html` をダブルクリック（マウスでも操作可能） |

- **音が出ない場合**: iOS は最初のタップまで音声を鳴らせません。一度画面をタップしてください。
- 縦持ち専用。ホーム画面に追加すると全画面で動きます。
- 触覚は `navigator.vibrate` を呼んでいますが、**iOS Safari は非対応**のため実機では鳴りません（Android では動作）。

## 選手を切り替える（§4.2 キャラクター定義項目）

敵ごとの構えと打ち方の違いは、このゲームの中身そのものです。
コードに直書きせず、**1人 = 1つのデータ**にしました。

```
FIGHTERS.gou = {
  build : 身長 / 頭 / 肩幅 / 半身の深さ / 前後の遠近 / 構えの高さ / 沈み / リーチ
  face  : 目の大きさ / 眉の既定角度 / 顎の幅 / 生え際
  color : 肌3色 / 髪 / 眉 / グローブ2色 / ショーツ
  habit : 呼吸の周期 / 目線の正直さ / ガードの堅さ / 足運び
  move  : 予告の大きさ / 速さ / 技ごとの予告倍率
  ai    : 使う型 / 間合いの取り方 / 読みやすさ
}
```

| | アラタ（打撃型） | ゴウ（レスリング型） | レン（スピード型） |
|---|---|---|---|
| 身長 | 0.90 | 0.855 | 0.945 |
| 肩幅 | 0.136 | 0.153 | 0.124 |
| 半身の深さ | 0.84 | 0.91（正対気味） | 0.78（深い） |
| リーチ | 1.00 | 0.92 | 1.10 |
| ストレートの溜め | 322 ms | 288 ms | 208 ms |
| ジャブの溜め | 126 ms | 108 ms | **59 ms** |
| 目線の正直さ | 0.85 | **0.52** | 0.70 |
| 使う型 | 打撃中心 | タックル・金網 | 差し合い中心 |

ゴウは**目線を上に残したまま腰が落ちる**（§4.2）ので、目線が当てにならず、
タックルの予告倍率が 0.68 と小さい。レンはジャブの溜めが 59ms しかなく、
差しは事実上見切れません。

## 打撃フォーム（文献に基づく実装）

「実際のフォームを分析して反映させる」という要求に対し、
バイオメカニクス研究とコーチング文献を調べ、**数値で裏を取ってから**実装しています。
出典は本ファイル末尾に一覧。

### 文献から確定した事実と、実装への反映

| 文献の記述 | 実装 |
|---|---|
| 打撃は近位から遠位へ体節が順に加速・制動する（proximal-to-distal） | 部位ごとに時間差を持つ運動連鎖 |
| クロスは「腰が先導し、肩が続き、腕が遅れ、拳が最後に弾ける」 | 腰 0.46→0.84、肩 0.66→0.94、腕 0.78→1.00 |
| **腕の伸展そのものは 60〜100 ms**（接触時間は 10〜20 ms） | 右ストレート全体 480ms のうち腕は最後の 22% ＝ **106 ms** |
| 拳速度：アマ 6〜9 m/s、エリート 9〜12 m/s | 到達距離 0.335×身長 ÷ 106ms ≒ **8.6 m/s** |
| **クロスでは腰が開始位置から約90度回る**（最大の力源） | `hipRot` を後ろ手の技で最大化 |
| 後ろ足は母趾球で押し込み、**踵が外へ回る** | 踵が浮き、爪先を軸に足が外向きへ回転 |
| 接触時、後ろ肩が顎に密着する | 打ち出しで肩が上がり顎へ寄る |
| **接触時に掌が下を向く**（回内）。人差し指・中指の拳頭で当てる | 伸展の最後の 1/3 でグローブが回内 |
| クロスの肘は矢状面のピストン運動で、回旋はほとんど無い | 肘は下がったまま拳の真後ろを追う |
| **フックは肘90度を保つ。**開くと遅い振り回しになる | 肩から拳までを `√(上腕²+前腕²)` に固定＝肘角90度が保たれる |
| フックは**拳・肘・肩が水平に一直線**。前腕は床と平行に回る | 拳の高さを肩の高さに固定し、肘を水平に先行させる |
| フックは前足を軸に回る（体重が前足へ乗る） | フックのときだけ軸足が前後入れ替わる |
| ジャブでは**前肩が上がって顎を守る** | 伸展に合わせて肩が上がる |
| アッパーは**肘90度**を保ち、膝のバネと腰で突き上げる。肘は体側に近い | 半径を固定した矢状面の円軌道＋沈み込みからの伸び上がり |

### 実装の骨格

腕は**上腕 0.172 ／ 前腕＋拳 0.185**（身長比、合計 0.357 ＝ 実際のリーチ）の2本の骨。
長さは固定し、拳の位置から**肘を逆算**（2関節IK）します。
肘の逃がし方が技ごとに違うので、同じIKでストレート・フック・アッパーが描き分けられます。

奥行きを持たせ、**打撃は標的（＝カメラ＝こちらの顔）へ収束**します。
拳が近づくほど中央へ寄って大きくなるのは透視投影の結果です。

### 追加で反映した文献（第2次調査）

| 文献の記述 | 実装 |
|---|---|
| **踏み込みジャブは「前足が接地するのと拳の到達が同時」** | 腕の伸展に合わせて前脚が前へ出る |
| エリートは**引き戻しを伸展と同じだけ**鍛える | 引き戻しを 260ms → **130ms**（伸展106msと同等）へ |
| **クロスの速度はリーチと相関**（Spearman r = 0.57） | 後ろ手の速さにリーチ係数を掛ける（レンのクロスが速い） |
| **ジャブの速度は習熟と相関**（r = 0.56） | 前手の速さは選手固有の `move.speed` で表現 |
| 手の最高速度は最大 9 m/s、平均最高 5.02 m/s（アマ16名） | 到達距離と伸展時間から算出される拳速が約8.6m/sで整合 |
| 16名中9名で**ジャブの最大速度がクロスより速かった** | ジャブの着弾はクロスより速い（アラタで278ms対552ms） |

### まだ足りていないところ

- 肩甲骨の前方突出（最終伸展で肩がさらに前へ出る分）
- 体重移動の可視化（前足に乗る量の定量化）
- 関節角度の生データによる検証（下記の制約により未取得）

### 調査の制約

この開発環境は組織のegressポリシーにより **`WebSearch` 以外の外部アクセスが遮断**されています。
PubMed Central / Frontiers / MDPI / arXiv / Semantic Scholar / OpenAlex / CORE、
Wikipedia までブロックされ、`curl` も全ドメインで接続不可でした。
そのため上記の数値は**検索結果の要約とコーチング文献から取得できた範囲**です。
モーションキャプチャの関節角度・角速度の生データ（時系列）が手に入れば、
`chain()` の時間区間と `fistPath()` の軌道をさらに正確にできます。

## 打撃フォーム（運動連鎖）

本物の打撃は腕から始まりません。地面から順に力が伝わります。

**後ろ足の踵が返る → 腰が回る → 体幹が回る → 肩が出る → 腕は最後**

初版は全部を同じ時間軸で動かしていました（＝手打ち）。
起こり(0)から接触(1)までを1本の時間軸とし、部位ごとに時間差を持たせています。

| 部位 | 動く区間 |
|---|---|
| 引き手 | 0.00 → 0.46（先に完了する） |
| 後ろ足の踵 | 0.30 → 0.70 |
| 腰 | 0.42 → 0.82 |
| 体幹 | 0.50 → 0.88 |
| 肩 | 0.58 → 0.92 |
| **腕** | **0.68 → 1.00（最後）** |

これにより、**踵と腰が先に動くのが最も早い予告**になります。

### 腕は2本の骨。長さは変わらない

初版は拳の位置を直接描いていたため、腕が伸び縮みしていました。
上腕 0.172 ／ 前腕＋拳 0.185（身長比、合計 0.357 ＝ 実際のリーチ）を固定し、
拳の位置から**肘を逆算**（2関節IK）します。肘の逃がし方は技ごとに違います。

| 技 | 拳の軌道 | 肘 |
|---|---|---|
| ストレート／ジャブ | 顎の横から最短距離で伸びる | 下がったまま拳の真後ろを追う |
| フック | **腕は伸びない。**肘角を保ち体幹の回転で振る | 肩の高さで拳より先行する |
| アッパー | 肘角を保ち、脚と体幹で下から突き上げる | 体の前で下 |

奥行き(z)を持たせ、カメラ軸（画面中央）へ向かう透視で投影しています。
**拳が近づくほど中央へ寄って大きくなるのは投影の結果**であって、
位置を直接描いているのではありません。インパクトでの拳の倍率は約4倍です。

### 顔（§4.1 §4.2）

彫刻的セルルック。**少数の大きな面**で構成し、線で描き込みません。

- シルエット：頬骨で張り、顎へ向けて締まる。顎先に少し角を残す
- 面：額の明面 / 頬骨の稜線 / 頬のくぼみ / 顎下の落ち影 / 右側の影面
- 目：アーモンド型。白目を減らし、上瞼のラインを内側から外へ細く抜く。
  二重の線を入れる。**瞳の位置で目線が必ず読める**（ゲーム上の必須要件）
- 眉：黒帯にせず、眉頭を太く眉尻へ細く抜く。集中・被弾・疲労で寄る
- 鼻：影の塊ではなく、稜線の明面＋小さな落ち影＋控えめな小鼻
- 口：結んだ線。疲労・被弾・力みで開き、マウスピースが覗く

表情は「通常・集中・疲労・被弊」を `stagger` と `fatigue` から連続的に作ります。

### 絵（§4.1）
Canvas 2D による疑似3D。写実ではなく**面で構成したセルルック**。
基調2色（濃紺・生成り）＋アクセント1色（朱）。墨は判定演出にのみ使用し、
顔を隠す墨影は使っていません。距離が近いほど下半身が画面外へ出るフレーミングです。

## モード

| モード | 内容 |
|---|---|
| **シチュエーション** | 局面を1つ切り取って繰り返す。12局面 × 4章。★3段階評価 |

| 試合 60秒 | 仕様書 §13 第2段階。敵AIがパターンを条件付きで接続する |

### シチュエーションについて

サッカーゲームの「パスを受けて、どこへ撃つか一瞬で決める」局面練習と同じ構造です。
MAAi のコアループは元々「1回の攻防」なので、**局面がそのまま最小単位**になります。

| 章 | 局面 |
|---|---|
| 1 見る | 右を止める / 外へ抜ける / 差しを捌く / 1-2 を読む |
| 2 返す | 隙を突く / 拍に乗せる |
| 3 間合 | 蹴りの間合い / 中に入る / 金網を背負う |
| 4 組み | タックルを切る / 二択を見抜く / フェイントを置く |

★1 クリア　★2 被弾なし　★3 PERFECT 規定回数以上。前の局面をクリアすると次が解放されます。

**重要な設計判断：状況は固定、相手が出す技はプールから抽選します。**
毎回同じ答えだと「読む」ゲームではなく「順番を覚える」ゲームになるためです。
たとえば「二択を見抜く」は tackle / straight / hook から毎回抽選されるので、
腰が落ちたか肩が溜まったかを実際に見るしかありません。
同じ技が2連続で出ないようにもしています。

## 構え — このゲームの土台

両者とも**オーソドックス（左構え）**。半身に構え、左半身が前です。
ここが正しくないと、ジャブとストレートが単なる左右の鏡像になり、**差し合いが成立しません**。

| | 左＝前手（リード） | 右＝後ろ手（リア） |
|---|---|---|
| 位置 | 顔より前へ差し出す。カメラに近い＝画面では中央寄り・低い・大きい | 顎の横。奥にある＝小さく、高い |
| 溜め | 肩が既に前にあるので**ほとんど無い** | 肩を溜め、腰が回り、後ろ足の踵が返る |
| ジャブ | 溜め110ms・着弾250ms・ダメージ5 | — |
| ストレート | — | 溜め280ms・着弾480ms・ダメージ11 |

### 読める技と、読めない技

主観時間の深さと長さは**技ごとに違います**（各技の `read` 値）。
予告が大きい技ほど深く長く遅くなり、予告が無い技はほとんど遅くなりません。

| 技 | 手 | 減速率 | 考える実時間 | PERFECT幅（実時間） |
|---|---|---:|---:|---:|
| 左ジャブ | リード | 0.34 | 506 ms | ±205 ms |
| 左フック | リード | 0.36 | 792 ms | ±196 ms |
| 右アッパー | リア | 0.31 | 968 ms | ±223 ms |
| 右ストレート | リア | 0.26 | 1100 ms | ±271 ms |

つまり **「見えた」という報酬は、後ろ手の技にだけ与えられます**。
ジャブは殴るための技ではなく、**相手に防御を使わせるための道具**です。
ジャブに防御を使うと、続く一撃の読みが 0.7 倍に浅くなります（＝1-2 が通る）。

### 受ける手

**来る側の手でブロックし、来る側と逆へスリップする。**

- 相手の右ストレートは**自分の左顔面**へ来る → 左を長押し／右へスリップ
- 相手の左ジャブは**自分の右顔面**へ来る → 右を長押し／左へスリップ

逆の手で受けると肩越しになり、軽減が 70%→52% に落ち、PERFECT にならず有利状態も取れません。

## 操作（§6）

画面を左右半分に分け、**開始した領域・方向・片指／両指**で技が決まります。
長さや速さでは技を分けません。左タップ＝前手（速い・軽い）、右タップ＝後ろ手（遅い・重い）。

| 入力 | 遠距離 | 打撃距離 | 密着距離 |
|---|---|---|---|
| 左タップ | 左前蹴り | 左ジャブ | 左ショートフック |
| 右タップ | 右ローキック | 右ストレート | 右肘 |
| 内側スライド | ミドルキック | フック | 肘・膝 |
| 上スライド | ハイキック | アッパー | 膝 |
| 外側スライド | 回り込み／スリップ | 回り込み／スリップ | 横へ動く |
| 長押し | 左右ガード | 左右ガード | フレーム |
| ガードを離す | クイックカウンター | クイックカウンター | 押し返し |
| 両指 上 | 前進 | 前進 | 押し込み |
| 両指 下 | 後退 | 後退／スウェー | 離れる |
| 両指 中央 | （届かない） | タックル | ボディロック |
| 両指 長押し | 低い構え | スプロール | 組み防御 |

### 1. 主観時間の減速率を技ごとに可変にした（§9.1）

仕様の固定値（Time Scale 0.25／選択時間 最大1.2秒）をそのまま実装すると、
**PERFECT が原理的に取れなくなります**。

- 右ストレートは予備動作開始からインパクトまで 440ms
- 減速開始から接触まで残り約 300ms
- 0.25倍だと実時間 1.2秒を超え、上限で先に通常速度へ戻る
- 戻った後に PERFECT 判定幅（±70ms）が来るため、スロー中に PERFECT を取れない

そこで **「攻防選択の実時間が常に約1.1秒になるよう、技ごとに減速率を決める」** 方式に変更しました
（`TS.CHOICE_REAL = 1100`）。結果として：

| 技 | 減速率 | PERFECT 幅（実時間） |
|---|---:|---:|
| ジャブ | 約 0.18 | ±約390ms |
| 右ストレート | 約 0.23 | ±約300ms |
| フック | 約 0.28 | ±約250ms |

**大きい技ほど減速が浅く、精度が要求される**という難易度勾配が自然に生まれます。
仕様の 0.25 は「右ストレートの場合の値」として妥当でした。

### 2. 読み成立を予備動作の 70% 地点にした（§9.1）

32% 地点で減速させると予備動作をほぼ通常速度で見られず、「読んだ」感が出ませんでした。
70% 地点にすると、**通常速度で肩と目線を見る → 読めた瞬間に世界が遅くなる**という
体験の順番が成立します。

### 3. 有利状態は PERFECT のみ（§9 の記述どおりに厳格化）

GOOD 回避にもカウンター受付を与えると、雑に振っても成立してしまいました。
GOOD/EARLY は相手の姿勢を崩すだけにしています。

### 4. カウンターの PERFECT 判定を「拍への着地」で行う（§9 §14）

有利状態中の攻撃が **拍（100BPM / 600ms）に着地したとき** PERFECT カウンター（1.8倍）。
§14 の「打撃音は通常速度へ復帰した拍へ着地させる」を、演出ではなく**判定**にしました。
リズムが攻撃側にも意味を持ちます。

### 5. 構えたガードへの打ち込みを割に合わなくした（§10）

初期実装ではランダムに連打するだけで KO できてしまいました。
相手が構えている間はダメージが約 1/4 になり、スタミナを余分に失い、
38% の確率で差し返しを受けます。**隙（予備動作中・硬直中・崩れ中）を突く**動機付けです。

### 6. 半身の構えと、リード／リアの非対称化（§4.2 §6）

初版は両手が同じ高さの**正対（スクエア）**で、ジャブとストレートが左右の鏡像でしかありませんでした。
これでは差し合いが発生しないため、以下を実装し直しています。

- 体幹を約35度ひねった半身の投影（前肩は外へ大きく、後ろ肩は中央寄りに小さく）
- 前脚は手前・大きく・低く、後ろ脚は奥・小さく・高く。後ろ足の踵は打ち出しで返る
- 前手は溜めずに伸び、後ろ手は肩を引き腰を回してから飛ぶ
- 腰の回転量を `hand === 'rear'` のときだけ大きくする（＝ストレート最大の予告）
- 主観時間の長さを技の `read` 値で可変にし、ジャブには「見えた」を与えない

### 7. ジェスチャー認識：1フレーム内で完結するフリックを取りこぼさない（§7）

実機のフリックは 60ms 程度で終わることがあり、毎フレームの判定だけでは
`pointerdown`→`pointerup` が同一フレームに収まって無効入力になっていました。
`pointerup` の時点でも最新座標で判定を回しています。

### 8. 打撃を人体としてありえる挙動に限定（§10）

初版には物理的にありえない挙動が3つありました。

- **連打・同時打ちのロックが一切なかった**。毎フレーム打て、左右同時にも打てた
- **拳が伸びるほど大きくなっていた**。遠ざかるのに拡大＝遠近が逆
- 画面隅から相手の顔まで**直線移動**していた。溜めも、顎の横からの発射も無かった

現在は打撃を「溜め → 伸展 → 接触 → 引き戻し」の1サイクルとして扱い、次の制約を課しています。

| 制約 | 実装 |
|---|---|
| 同時に2発は打てない | 体幹が空くまで `punchLock`（伸展の62%地点まで） |
| 同じ手は1サイクル塞がる | `handReady[side] = 伸展 + 引き戻し` |
| ただし 1-2 は繋がる | 入力を 220ms 保持し、空いた瞬間に出す |
| 両手を組み防御に使っている間は打てない | 両指長押し中は入力を破棄 |
| 打つ手のガードは解ける | その側の `guard` を解除（＝空いた側は被弾する） |
| 拳は遠ざかるほど小さい | 半径を構え時 → `bh*0.052` へ縮小 |
| 顎の横から発射する | 構え → 顎の横 → 相手 の2次ベジェ |
| 打っていない手は下げない | わずかに締めて顎の位置に残す |
| 前腕は肩側が太く手首側が細い | 根元幅を固定し、手首側だけ拳に追従させる |

### 9. 見切りの猶予を人間の反応時間から決め直す

「タイミングがシビアすぎる／成功と失敗の区別がつかない」という指摘を受けて計測したところ、
**NORMAL の左ジャブは物理的に不可能**でした（人間の視覚反応 約250ms に対し、押せる猶予 217ms）。
猶予を `溜め × 倍率 + 定数` から決め直しています。

| 難易度 | 技 | 押せる猶予 | 反応時間(250ms)を引いた余裕 |
|---|---|---:|---:|
| NORMAL | 左ジャブ | 387 ms | 137 ms |
| NORMAL | 左フック | 502 ms | 252 ms |
| NORMAL | 右ストレート | 582 ms | 332 ms |
| BEGINNER | 左ジャブ | 730 ms | 480 ms |
| BEGINNER | 右ストレート | 1240 ms | 990 ms |

ジャブだけは意図的に厳しいまま残しています（前手は溜めが無い＝読めないのが正しい）が、
不可能ではなくなりました。

### 10. 成功と失敗を区別できるようにする

表示が重なり合い、何が起きたのか読み取れない状態でした。次のように整理しています。

**試合中の色は意味で固定**
- **赤 = 被弾**。それ以外には使わない
- 淡い青白 = 見切り成功　／　生成り = 防いだ

**表示位置を固定**（重ねずに上書き）
`見切り` → `技名` → `判定` の3スロットを画面上部に固定し、
出ている間だけ薄い帯を敷いて顔に文字が重ならないようにした。

**画面の縁が光る** — 見切り成功／防御成功／被弾で色が変わる。一目で分かる。

**音で分かる** — 見切り PERFECT は2音の上昇、GOOD は1音、遅いは低い1音。

**攻防の内訳** — リザルトに1行ずつ残る。§16 の計測項目にもそのまま使える。

```
1  右ストレート   押せず    被弾 11
2  右ストレート   見切った  PERFECT
3  左フック      押せず    被弾 11
4  左ジャブ      見切った  PERFECT
```

**起こりの合図** — 溜めが始まった部位が 170ms だけ光る。難易度によらず表示する。

### 11. ガード帯と打撃帯を上下で分ける

「ガードをしたいだけなのに打ち返してしまう」という指摘への対応です。
原因は、長押し(220ms)に届かない短い接触が**タップ＝打撃**として解釈されていたこと。
守るつもりの指が攻撃を出し、その硬直で次の起こりが見えなくなっていました。

画面を**左右で手を、上下で構えるか打つかを**分けました。

| 帯 | 入力 | 行動 |
|---|---|---|
| **上＝ガード帯** | 触れる | その側のガード。**触れた瞬間から**構える（220ms待たない） |
| | 下へスライド | 構えていた手をそのまま振り下ろして打つ |
| | 外へ / 内へ | スリップ / フック |
| | 離す | 構えを解く。有利中ならクイックカウンター |
| **下＝打撃帯** | タップ | ジャブ / ストレート |
| | 上へ / 内へ / 外へ | アッパー / フック / スリップ |
| | 長押し | ガード |

**ガード帯からは何をしても打撃になりません。** また、触れた瞬間に構えが立つので
「守れたのか分からない」時間がなくなります。

副産物として、指を止めずに**守りから攻めへ繋がる**動きが生まれました
（構えていた手を下へ振り下ろす）。

### 12. 描画が止まっていた不具合（BEGINNER）

BEGINNER の見切り受付表示に変数名の取り違え（`rel` 未定義）があり、
**受付が開いている間ずっと毎フレーム例外が投げられていました**。
例外以降の描画（レターボックス、縁の発光、ビネット）が丸ごと飛ぶため、
BEGINNER でプレイすると成功のフィードバックが表示されない状態でした。
「成功が分からない」の直接原因です。

### 13. 見切っても遅くならなかった不具合

「読んだ！と出ても遅くならない」という指摘を計測したところ、
**主観時間が実時間で 100〜245ms しか続いていませんでした**（設計値は約 1100ms）。

原因は、見切りを「指を置いた瞬間」にしたことの副作用です。
指を置く → 見切り成立 → 減速開始、の直後に、**同じ指が長押し(220ms)やタップとして
「行動確定」に化けて、始まったばかりの減速を即座に終わらせていました**。

長押しを「まだ決めていない構え」として扱うように変更しました。

| 入力 | 意味 | 主観時間 |
|---|---|---|
| 長押し | 構えただけ。まだ決めていない | **続く**（接触まで） |
| スライド / タップ / 両指 | 行動確定 | 最低 300ms を保ってから通常速度へ |

構えたまま拳が来るのを見て、そこから指を滑らせて回避に切り替えられます。

| | 修正前 | 修正後 |
|---|---:|---:|
| 押して構えたまま | 245 ms | **1134 ms** |
| 押してすぐ離す（タップ） | 100 ms | 313 ms |
| 押して 400ms 後に外へ | 232 ms | 416 ms |

あわせて、**構え続けた防御の質を「押した時刻」ではなく「どれだけ早く見切ったか」で決める**
ようにしました。前半で見切っていれば構えたままでも PERFECT になり、有利が取れます。
早く読むことが、回避だけでなくガードでも報われます。

### 14. 入場〜対峙の 4 拍（心の準備）

開始と同時に相手が殴りかかってきて、構える間がありませんでした。
実際のMMAも離れた位置から詰めてから始まります。

開始後の 4 拍（2.4秒）を**対峙**にしました。

- 相手は金網際（通常の 0.30 倍のサイズ）から歩いて定位置まで詰めてくる
- 毎拍つよい足音が鳴る。ここで 100 BPM のテンポを掴ませる (§14)
- 4 つの拍マーカーが順に灯り、最後の 1 拍で「構えろ」→「来る」に変わる
- この間は相手は仕掛けてこず、こちらも打てない。ガードの構えだけ作れる
- **指を置くと残りを 0.75 拍まで詰めて始まる**（連戦でだれないように）
- 試合時間のカウントは「始め」から。対峙は消費しない

結果、開始から最初の攻撃まで約 2.9 秒になりました。

### 15. 主観時間を「見切って」発動させる（§9.1 発動条件）

初版は予備動作が始まると**主観時間が自動で発動**していました。
これではプレイヤーは一度も「見切る」という行為をしておらず、
ただ遅いパンチを避けるだけのゲームになります。
仕様書 §9.1 が「面白さが確認できた後に移行する」としていた段階へ進めました。

**見切り＝画面に指を置いた瞬間。** 新しい操作は増やしていません。
既存の12ジェスチャーはすべて「指を置く」から始まるので、
**予備動作の間に指を置けたら主観時間が開き、置いた指をどこへ動かすかをスローの中で決める**
という二段構えになります。

| 押した位置 | 見切り | 減速率 | 考える実時間 |
|---|---|---:|---:|
| 予備動作の前半（〜35%） | 見切った | 0.27 | 1595 ms |
| 予備動作の後半 | 読んだ | 0.30 | 1100 ms |
| 拳が出てから | 遅い | 0.18 | 495 ms |
| 押さない | — | — | スローなし |

早く見抜くほど深く長く遅くなります（§9.1「早く予備動作を見抜くほど、
拳が遠い段階からスローになる」）。

**連打では見切れません。** 読むものが無いのに指を置くと 300ms のあいだ読めなくなります。
結果として「攻撃を出した直後はカウンターを読めない」という、
実際のMMAと同じリスクが生まれます。

**ガードだけは早く構えても損をしません。** 接触の瞬間に上がっていれば止まります
（早すぎる構えを MISS にすると、見切れないジャブに対して手も足も出なくなるため）。
接触に合わせて出したときだけキャッチ＝PERFECT になり、有利を取れます。
代わりにガード中はスタミナが毎秒3ずつ減り続けるので、亀にはなれません。

検証結果（60秒の試合、NORMAL）:

| プレイ | 結果 |
|---|---|
| 何も触らない | 11秒でテイクダウン負け（見切り 0/8） |
| 見切るが動かない | 16秒でKO負け — 見切っただけでは助からない |
| 見切って正しく受ける | 60秒完走、判定へ（見切り 42/42、残HP 18） |

### 16. 主観時間を「知覚できる」ものにする（§9.1 §14）

減速率と判定は正しく動いていたのに、**プレイヤーには遅くなったことが分からない**という
致命的な状態でした。スローモーションは何かが遅く動いて初めて知覚できますが、
減速の瞬間の画面には動いているものがほとんど無く、暗いオーバーレイを重ねても
元から暗い画面では変化が見えなかったためです。

参照は GTA5 の運転スロー。**速度の基準になるものを画面に置く**ことで解決しました。

| 手法 | 役割 |
|---|---|
| 塵と汗 | ゲーム内時間で飛ぶので、減速すると宙で止まりかける。**これが速度計** |
| ラジアルブラー | 世界だけを中心へ流す。拳と自分のグローブは後から鮮明に描き直す |
| 集中線 | 46本を黄金角で散らし、中心へ吸い込ませる |
| レターボックス | 状態が変わったことを一目で示す |
| カメラの寄り | 減速に合わせて 1.0 → 1.085 |
| 拳の残像 | 7枚。軌跡そのもので「遅い」を示す |
| 入り／出の一撃 | 55ms の静止＋白フラッシュ＋衝撃波リング。出る時は放射線 |
| 音 | 高域が抜けるスイープ＋沈むサブ＋マスター音量が落ちる。ローパスは 380Hz まで閉じる |
| 判断の残り時間 | レターボックス上の朱いバーが接触に向かって減る |

暗くしすぎると予備動作が読めなくなるため、**ぼけた世界は暗く落とし、
拳と汗は鮮明なまま重ねる**順序にしています。相手の胴体だけ加算光で起こしています。

#### 描画品質の自動調整

効果を全部入れると描画コストが上がるため、フレーム時間を実測して自動で落とします。
`ブラー → 汗の上限 → 解像度` の順に下げ、余裕が戻れば逆順に戻します。
ブラーは合成を 1/2 解像度で行い、画面全面への書き込みを 1 回に抑えています
（この最適化でブラーのコストは 23fps 分から 4fps 分に下がりました）。

### 17. 敵AIの距離運用（§5 §17.1）

- 前進・後退の向きが逆で、相手が「後退」するたびに密着距離へ入っていた
- 密着距離用のパターンが無いため、そこへ入るとAIが1つのパターンに固着していた
- パターン接続グラフに到達不能なノードがあり、実際には3種類しか出ていなかった

現在は10パターンすべてが出現し、遠距離へ離れれば蹴りが、
打撃距離ではジャブ・ストレート・フック・アッパー・タックルが混ざります。
密着距離は仕様どおり自由攻防を実装せず、1.6拍で打撃距離へ戻します。

## 次に検証したいこと

1. ジャブ（減速率0.34／506ms）とストレート（0.26／1100ms）の差が適切か。
   ジャブは「反応する技」、ストレートは「読む技」という住み分けが成立しているか
2. 予備動作の何 % で減速を始めるのが良いか（現在 70%）
3. 自分の腕がどれだけ相手の予備動作を隠してよいか（§4 のガードのリスク）
4. 受ける手（来る側の手でブロック）のルールが直感的か、それとも煩わしいか
5. 拍への着地でカウンター判定する設計を残すか
6. 主観時間を自動発動のままにするか、正しい初動入力を条件にするか

### キャラクター表現について

本試作は**多関節の写実的3Dを必要としない**という前提で作っています。
実際のMMAの予備動作は数センチ・数フレームで、スマートフォンの画面では読めません。
主観時間で遅くしたときに「見えた」と感じさせるには、**誇張された動き**が要ります。

必要なのは表面の忠実さではなく、**因果の正しさ**です。
「前肩が既に前にある → だからジャブは溜めが要らない → だから読めない」
という骨格が正しければ、面で構成したセルルックで十分に成立します。
逆にここが嘘だと、どれだけ精巧なモデルでも「MMAではない」と感じられます。

本試作のポーズ定義（どの部位が、どれだけ、何ms動くか）は、
そのまま 3D 側のアニメーション仕様として使えます。

## ファイル構成

```
maai/
├── index.html   # 全部入り（設定 / 音 / 入力 / 時計 / 戦闘 / AI / 描画 / シーン）
└── README.md
```

単一ファイルなのは、**実機へ送るまでの摩擦をゼロにするため**です。
仕様が固まって Unity へ移す段階では、`index.html` 内のセクション区切り
（`1. CONFIG` 〜 `22. 起動`）がそのままモジュール境界になります。
