# MAAi 時間設計の基準

数値を勘で置くと「実装は動いているのに、人間には一度も到達できない機能」が
生まれる。実際に、到達不能なPERFECT要求のせいで「返し」が実プレイで
0回になっていた（見切りPERFECT 0/24、返し 0/24）。
以下はその再発を防ぐための基準と手順。

## 人間側の実測値（コード内 `HUMAN`）

| 定数 | 値 | 根拠 |
|---|---:|---|
| `SRT_MEAN` | 231ms | 単純視覚反応の平均。n=1469、18〜65歳。機材遅延を補正すると213ms。健常成人はおよそ200〜300ms。Woods et al., Front Hum Neurosci (2015) PMC4374455 |
| `SRT_FAST` | 190ms | 同標本の速い層（およそ下位10%）。腕の立つプレイヤーの想定 |
| `DEVICE` | 70ms | 端末の遅延。iPhone 12 の touch-to-photon 実測 78ms（960fps撮影）。iPhone 5 は55ms、iPhone 4 は85ms |
| `HICK_A` / `HICK_B` | 200ms / 150ms per bit | 選択反応 RT = a + b·log2(n+1)。Hick (1952)、Proctor & Schneider QJEP (2018) のレビューによる代表値 |

## そこから導く値

- **`REACT_FLOOR` = SRT_FAST + DEVICE = 260ms**
  見切りの質を測る起点。予告が網膜に映ってから指が触れるまでの、
  誰にも詰められない時間。ここを差し引かずに「予告の35%以内」を
  PERFECT にしていたため、ジャブは61ms以内という要求になっていた。

- **`CHOICE_NEED` = HICK_A + HICK_B·log2(7) + DEVICE ≒ 691ms**
  主観時間の中で6通りから選ぶのに要る実時間。
  スロー窓（TS.CHOICE_REAL = 1100ms）はこれを上回る必要がある。

- **`GAP_MIN` = CHOICE_NEED × 1.3 ≒ 898ms**
  着弾から次の予備動作までの最小間隔。
  「結果を見る → 選択反応を1周する → 構え直す」に要る時間。

- **PERFECTの窓 = max(予告 × 0.35, 90ms)**
  短い技で窓が潰れないよう下限を置く。

## 手順（タイミングに触ったら必ず通す）

```
node scratchpad/reach.mjs    # 全技 × 全難易度の到達可能性を監査。到達不能が1件でもあれば異常終了
node scratchpad/skill.mjs    # 反応速度別（速い/普通/遅い）の実プレイ分布
node scratchpad/allsit.mjs   # 12状況の回帰
```

`reach.mjs` が見るもの:
- 速い人（260ms）が PERFECT に届くか
- 平均的な人（301ms）が見切りそのものに届くか

## 現状の実測（参考値）

| プレイヤーの反応 | PERFECT見切り | 返し | 平均被弾 |
|---|---:|---:|---:|
| 速い（260〜340ms） | 21/24 | 18/24 | 2.1 |
| 普通（330〜450ms） | 6/24 | 13/24 | 2.6 |
| 遅い（450〜600ms） | 1/24 | 4/24 | 7.0 |

腕前がそのまま結果に出ていれば健全。どれかの層が全滅していたら、
その層にとって機能が存在しないのと同じ。

## 入力から体が動くまで（実測 2026-09）

体感を語る前に、押してから画面が変わるまでを測ること。
以下はすべて headless Chromium（`__noGL=1` で2D経路）での実測値。

### 直したもの

| | 前 | 後 |
|---|---|---|
| 押してから拳が動きだす | **89ms**（しかも溜め動作なし） | **19ms**（1フレーム） |
| 指を170ms以上押していた場合 | **打撃が出ない** | 出る |
| 指を220ms以上押していた場合 | **打撃が出ない**（HOLD扱い） | 出る |
| 伸展の速度曲線 | `easeOut` = 接触へ向けて減速 | `out^1.7` = 加速しながら接触 |
| 接触直前の速度 | 最高速の **7%** | 最高速付近 |
| 拳の遠近（構え→伸展） | 72px → 69px（**4%**） | 72px → 30px（**58%**） |
| 至近距離での拳の遠近 | 72px → **115px**（伸ばすほど大きい） | 72px → 30px |

### なぜそうなっていたか

- **打撃は `pointerup` の `TAP` でしか出なかった。** `TAP_MAX_MS = 180` を
  超えると `INVALID`、`HOLD_MS = 220` を超えると打撃帯の長押しガードになり、
  離しても何も起きなかった。人が親指で押す時間は 80〜250ms に散らばるので、
  **指を離す速さで打撃の有無が決まっていた**。これが「空振り入力38%」の正体。
  → 打撃帯の長押しガードを廃止（ガードは上帯だけの役目）。
    動かさずに離せば、押していた長さに関わらず必ず出る。

- **押している間、画面上で体が何も動いていなかった。**
  → 触れた瞬間から拳が引かれる（`p.wind`）。見た目は `1-exp(-t/40)` で
    立ち上げるので1フレーム目から動く。

- **伸ばした先の拳の大きさを `V.bh`（相手の画面上の大きさ）に結びつけていた。**
  自分の拳の見かけの大きさは自分の目からの距離だけで決まる。相手が近いほど
  自分の拳が大きくなるのは誤り。
  → `endR = min(V.bh*0.052*0.62, b.r*0.42)`。相手の頭に対して正しい比で
    着弾し、かつ構えより必ず小さくなる。

### 溜め（`WIND_FULL = 260ms`）

指を置いてから離すまでが、そのまま打撃の溜めになる。

| | 効果 |
|---|---|
| ダメージ | ×(1 + 0.38·wind) |
| 到達時間 | ×(1 + 0.14·wind) |
| スタミナ | ×(1 + 0.30·wind) |

実測：溜め0 → 与ダメ4.7 / 到達350ms、溜め満 → 与ダメ6.9 / 到達394ms。
速さを取るか重さを取るかが、指の置き方そのものになる。
`Rec` の `swing` イベントに `wind`（0〜100）を記録し、記録画面に
「溜め 平均◯% 浅/中/深/満」として出る。
