# MAAi -間合-　実装仕様書 v6.5

縦持ち一人称MMA。**予備動作を見切った者だけが、遅くなった世界を手に入れる。**

この文書は、他の実装者がこのゲームを再現するための仕様である。
数値はすべて `index.html` から抽出したもので、測定値は headless Chromium での実測値。

読みやすい版：https://claude.ai/code/artifact/00da4a1f-9bb2-4f32-8151-3256aec52db5

関連文書：`TIMING.md`（タイミングの根拠と変更手順）／`DEVICE.md`（端末制約と触覚設計）／`MODEL_SPEC.md`（3Dモデル受け入れ仕様）

## 0. 設計原則

中心は一つだけ。**相手の予備動作を見切った瞬間、主観時間が遅くなる。**
遅くなった時間の中で防御・回避・迎撃・打ち返しを選び、接触の瞬間に一気に解決する。

再現するうえで外してはいけない判断が4つ。

1. **主観時間は自動発動しない。** 予備動作の間に指を置けたときだけ開く。
   押さなければ通常速度で捌くしかない。「見た」ことに報酬を出すための唯一の仕組み。
2. **ガードは凌ぐだけ。** 攻めには繋がらない。ガードが有利も生む設計では、
   他を選ぶ理由が消えて選択肢が実質1つになる（実プレイで確認済み）。
   **凌ぐか、外すか**が毎回の決断であること。
3. **判定は実時間で、進行は主観時間で。** 入力・UI・触覚は `Clock.real`、
   敵アニメと攻撃進行は `Clock.game`。混ぜると、遅くなった時間で考えている間に
   「遅い」と判定される。
4. **人が届かない要求を作らない。** 予告が網膜に映ってから指が動くまでの
   約190msは誰にも詰められない。判定の起点はそこに置く（§5, §16）。

### 面白さの4本柱

1. 見切ったときの爽快感
2. 遅くなった時間で攻撃を組み立てられる
3. それが相手にしっかり決まる
4. 強い敵はそこも読んでくる（ストレスにならない範囲で）

仕様の各項目はこのどれかに紐づく。

## 1. 構成と依存

全体が単一のHTMLファイル。ビルド工程は無い。実機へ送るまでの摩擦をゼロにするための構成で、
Unity等へ移す段階ではファイル内のセクション区切り（`1. CONFIG` 〜 `22. 起動`）が
そのままモジュール境界になる。

| 層 | 実装 | 備考 |
|---|---|---|
| 描画（相手） | three.js r128 + GLTFLoader（CDN） | GLBをbase64で内蔵。Mixamoクリップをリターゲットして再生 |
| 描画（自分の腕・UI・エフェクト） | Canvas 2D | 常に3Dの上に重ねる |
| 3Dが使えない場合 | Canvas 2D の擬似3D描画へ自動フォールバック | `GL3.boot()` が失敗しても遊べること |
| 音 | Web Audio（合成のみ・音源ファイルなし） | §13 |
| 保存 | localStorage | 進捗・タイミング補正・プレイ記録 |

テスト用フック `window.__noGL=1` を先に立てると `GL3.boot()` を飛ばして2D経路になる。
ソフトウェアGLでは実測がフレーム律速になるため、入力遅延の計測は必ずこの経路で行う。

## 2. 画面と帯

縦持ち固定・一人称。画面は**左右で手**、**上下で構えるか打つか**に分かれる。
この2軸だけで全操作を構成する。

| 領域 | 範囲 | 役割 |
|---|---|---|
| ガード帯 | y < 0.66·H | 触れた瞬間に構える。**ここからは何をしても打撃にならない** |
| 打撃帯 | y ≥ 0.66·H | タップとスライドで技。押している間は溜め |
| 左半分 / 右半分 | x < 0.5·W / ≥ | 左手（リード）/ 右手（リア） |

**なぜ帯を分けるか。** 「守りたいだけなのに打ってしまう」が起きないため。
防御と攻撃を同じ入力の解釈違いにすると、緊張した場面で必ず事故が起きる。

**相手の投影**：`V.bh`（相手の身長の画面上px）と `V.faceX/faceY` が距離から算出され、
あらゆる着弾点の基準になる。実測（390×844の画面）：遠距離 613px / 打撃距離 1333px / 密着距離 2211px。

## 3. 二重時計

| 時計 | 進み方 | これで測るもの |
|---|---|---|
| `Clock.real` | 実時間。常に等速 | 入力・UI・演出・触覚・反応時間の記録 |
| `Clock.game` | `realDt × scale` | 敵アニメ・攻撃進行・接触時刻・硬直 |

```
gameDt = min(rawDt, 50) × scale        // 50ms超のフレームは切り捨てる
if (freeze) gameDt ×= 0.02             // ヒットストップ
scale は rate ms かけて target へ線形に寄る
```

### 主観時間の段階

| 定数 | 値 | 意味 |
|---|---:|---|
| `TS.OBSERVE` | 1.00 | 通常速度 |
| `TS.READ` | 0.35 | 見切った直後の基準 |
| `TS.CHOICE` | 0.25 | 選択中の基準 |
| `TS.IMPACT` | 0.04 | 接触の瞬間 |
| `TS.ENTER_MS` | 120 | 減速に要する実時間 |
| `TS.EXIT_MS` | 100 | 復帰に要する実時間 |
| `TS.CHOICE_REAL` | 1100 | 攻防選択に与える実時間。**減速率はここから逆算する** |
| `TS.MIN_SLOW_REAL` | 300 | 行動を決めても最低これだけは遅いまま（手応えのため） |
| `TS.MAX_CHOICE_REAL` | 1800 | 安全弁。超えたら強制復帰 |

### イベント時刻の復元

ポインタイベントの `e.timeStamp` は rAF のタイムスタンプと同じ時間軸にある。
キュー処理時点の時刻で判定すると 60Hz で最大17ms遅れ、
**60Hz端末と120Hz端末で実効判定窓が変わる**。必ずイベント自身の時刻から復元すること。

```
evReal(ts) = real + clamp(ts − tickAt, 0, 50)
evGame(ts) = game + clamp(ts − tickAt, 0, 50) × scale
```

## 4. 入力認識

ポインタイベントから離散ジェスチャーを作りキューへ積む。
判定は**イベント発生時刻**で行い、処理は次フレームで良い。

### 閾値（すべて画面短辺比）

| 定数 | 値 | 用途 |
|---|---:|---|
| `TAP_MAX_MOVE` | 0.03 | タップとみなす最大移動量 |
| `SWIPE_DIST` | 0.07 | スワイプ成立距離 |
| `DIR_TOL` | ±30° | 上下左右の許容角 |
| `DUAL_WINDOW` | 140 ms | 両指入力とみなす着地間隔 |
| `HOLD_MS` | 220 ms | 両指長押し（スプロール）の成立時間 |
| `GUARD_IGNORE` | 0.05 | 長押し中に許す微動 |
| `WIND_FULL` | 260 ms | 溜めが満ちるまでの実時間 |

### 判定の優先順位

1. **両指** — 140ms以内に両側へ着地し、両方が同方向へ7%移動（上=前進 / 下=後退 / 中央=タックル）、
   または両方が220ms静止（スプロール）
2. **スワイプ** — 7%移動し、主要方向から±30°以内。左右は**内／外**へ変換（左指の右＝内）
3. **タップ** — **移動量3%未満で離した**。押していた長さは問わない

> **ここは実測で作り直した部分。**
> 以前は `TAP_MAX_MS=180` があり、170ms以上押していると `INVALID`、
> 220ms以上で打撃帯の長押しガードになって、離しても何も起きなかった。
> 人が親指で押す時間は 80〜250ms に散らばるので、**指を離す速さで打撃の有無が決まっていた**。
> 打撃帯の長押しガードを廃止し（ガードは上帯だけの役目）、時間上限を外した。

### 両指ジェスチャーとの共存

スワイプが成立しても、両指の可能性が残る間は**1フレームだけ保留**する。
次の rAF（または指を離した瞬間）に両指が成立していなければ、
**記録した発生時刻のまま**単独スワイプとして発火する。
保留を入れないと両指入力が片指スワイプに化け、入れっぱなしにするとスワイプが常に1フレーム遅れる。

## 5. 見切り判定

**指を置いた瞬間が「初動を見切った」瞬間。** あらゆる操作はここから始まる。

### 受付条件

```
el = t − ex.t0                          // 予告開始からの経過（主観時間）
readable = 攻防中 かつ 未見切り かつ
           el ≤ tell × diff.readWindow + diff.readGrace
```

読むものが無いのに手が出た場合は**過剰反応**として `flinchUntil = t + 300ms`。
この間は見切れない。連打で見切れてしまうと「間」が消える。

### 質の決定

```
perfW   = max(tell × 0.35, 90)          // PERFECT窓。短い技で潰れないよう下限90ms
after   = max(0, el − REACT_FLOOR)      // REACT_FLOOR = 260ms
rel     = after / tell
guessed = el < REACT_FLOOR × 0.55       // = 143ms。見たのではなく山を張った
```

| 条件 | 判定 | mul | 意味 |
|---|---|---:|---|
| `guessed` | GOOD | 0.85 | 当たったが読みではない |
| `after ≤ perfW` | **PERFECT** | 1.45 | 反応できる限界で捉えた |
| `rel ≤ 1.0` | GOOD | 1.00 | 予備動作のうちに反応した |
| それ以外 | LATE | 0.45 | 拳が出てから気づいた |

> **REACT_FLOOR を引く理由。** これを引かずに `rel ≤ 0.35` を PERFECT としていたとき、
> ジャブは61ms以内・ストレートは113ms以内という**到達不能な要求**になり、
> 実プレイで PERFECT が一度も出ず、返しも永久に起きていなかった。
> 判定の起点は「予告が出てから」ではなく「**人が反応できるようになってから**」に置く。

> **guessed を入れる理由。** 入れないと、予告を見ずに連打するのが最適解になる。
> ランダムに触るだけのボットが反応100msで PERFECT を取っていた（実測）。

### 減速率

```
remain = max(60, ex.impact − t)         // 接触までの残り（主観時間）
real   = TS.CHOICE_REAL × m.read × diff.readMul
         × fighter.readMul × mul × (readPenalty ? 0.7 : 1)
slowScale = clamp(remain / real, 0.10, 0.90)
```

「残りの主観時間を、与えたい実時間で割る」——これが減速率。
**技ごとの読みやすさ `m.read` がそのまま主観時間の長さになる。**
ジャブ（0.52）はほとんど遅くならず、右ストレート（1.00）は深く長い。

## 6. 主観時間の進行

| 遷移 | 条件 | 動作 |
|---|---|---|
| 減速開始 | 見切り成立 | `Clock.to(slowScale, 120)` ＋ 低域通過フィルタが閉じる |
| 強制復帰 | スロー突入から実時間1800ms | `Clock.to(1.0, 100)` |
| 行動確定で復帰 | 選択が確定 かつ スローに入って300ms以上 | 同上。300ms待つのは**見切った手応えを残すため** |
| 接触 | `Clock.game ≥ ex.impact` | `resolveExchange()` |

**仮の構え（soft）**：長押しは「構えただけ」で行動確定ではない。主観時間は続いたままなので、
構えたまま拳が来るのを見て、そこから指を滑らせて回避に切り替えられる。

## 7. 攻防の解決

接触の瞬間に一度だけ走る。**分岐の順序が仕様そのもの**なので、この順に評価すること。

### 0. 判定の格上げ

```js
if (ex.read && ex.slowed && ch) j = bestJudge(j, ex.read);
```

スロー中の選択は、接触からの距離ではなく**見切りの質**で評価する。
ここを入れないと、遅くなった時間の中でじっくり考えるほど MISS になる。

### 1. 打ち返し（看板の行為）

| 条件 | 結果 |
|---|---|
| `choice='attack'` かつ 見切り済み かつ PERFECT | **合わせた**。相手の拳が届く前に潰す。`reversal('counter')` → 完全な崩し ＋ `COUNTER_WINDOW×1.9 = 2375ms` の有利 |
| `choice='attack'` かつ 見切り済み かつ PERFECT以外 | **相打ち**。被弾 `dmg×0.55`、こちらの攻撃も通り、短い有利 |

> **この分岐は後から足した。** それまで `'attack'` はどの技の `safe` にも含まれず、
> 最後の else に落ちて**フルダメージ**だった。「見切って打ち返す」というゲームの看板行為が、
> 確実に損をする選択になっていた（実測：6回すべてPERFECTで見切り、6回すべて被弾）。

### 2. ガード

```js
still = Input.isHolding(guardSide) || ex.read   // 見切っていれば指を離しても保つ
want  = m.from > 0 ? 'R' : (m.from < 0 ? 'L' : null)
wrongHand = want && guardSide !== want         // 逆の手＝肩越し
```

| 状態 | 被ダメージ | その他 |
|---|---:|---|
| 指を離していた（未見切り） | dmg × 1.00 | 「ガードを離した」 |
| LATE | dmg × 0.35 | — |
| 正しい手 | dmg × 0.30 | スタミナ `−dmg×0.9` |
| 逆の手 | dmg × 0.48 | スタミナ消費 ×1.4 |
| スタミナ25未満 | 上記 × 1.9 | 「ガードが重い」 |

**ガードでは有利を取れない。** 凌ぐだけ。選択肢を1つに潰さないための最重要の判断（§0）。

### 3. 有効な回避（`m.safe` に含まれる）

| 判定 | 結果 |
|---|---|
| LATE | `dmg×0.35` |
| GOOD | 回避成功。スタミナ −9。短い有利（1250ms） |
| **PERFECT** | 回避成功。スタミナ −5。相手の `recover ≥ 340ms` の大技なら**返し**（2375msの有利）、それ以外は強い有利（1437ms） |
| スプロール PERFECT | 背後を取る。`reversal('back', 16)` |
| 迎撃 PERFECT / GOOD | 22 / 12 ダメージを与える |

### 4. 危険な対応 / 5. それ以外

`m.bad` に含まれる対応は `dmg×1.2`。それ以外の無関係な入力は `dmg×1.0`。無入力も同じ。

### 反撃の連鎖

| 定数 | 値 | 意味 |
|---|---:|---|
| `COUNTER_WINDOW` | 1250 ms | 基本の有利時間 |
| `COMBO_EXTEND` | 520 ms | 1発当てるごとに延びる |
| `COMBO_MAX` | 3 | 一度の有利で繋がる最大打数 |

> **延長しないと3連は繋がらない。** 600msでは1発しか入らず「攻撃を組み立てる」体験に
> ならなかった。逆に `dealDamage` の末尾で毎回有利を閉じていたため、窓を伸ばしても
> 繋がらない期間があった。上限に達したときだけ閉じること。

## 8. 打撃の物理

プレイヤー自身の拳は Canvas 2D で描く。
ここが「ただクリックしているだけ」かどうかを決める。

### 溜め（押している間）

```
視覚 wnd = 1 − exp(−(Clock.real − wind.t0) / 40)   // 1フレーム目から動く
威力 wind = clamp(押していた実時間 / 260, 0, 1)

引き手：x −= 0.045·W × wnd,  y += 0.030·H × wnd,  r ×= 1 + 0.22·wnd
```

| 溜め | 係数 | 効果 |
|---|---|---|
| ダメージ | × (1 + 0.38·wind) | 溜めた分だけ重い |
| 到達時間 | × (1 + 0.14·wind) | 届くのが遅れる |
| スタミナ | × (1 + 0.30·wind) | 余分に減る |

実測：溜め0 → 与ダメージ 4.7 / 到達 350ms、溜め満 → 6.9 / 394ms。
**速さを取るか重さを取るかが、指の置き方そのものになる。**

### 伸展

```
tt   = Clock.game − act.t0
out  = clamp(tt / act.dur, 0, 1)
u    = 戻り中 ? 1 − easeIn(back) : out^1.7      // 加速しながら接触する
chamber = act.wind × (1 − out)²

位置：構え → 顎の横 → 相手 の2次ベジェを u で辿る
大きさ：endR = min(V.bh × 0.052 × 0.62, baseR × 0.42)
        r = lerp(baseR × (1 + 0.22·chamber), endR, u)
```

| 実測項目 | 直す前 | 直した後 |
|---|---:|---:|
| 押してから拳が動きだすまで | 89 ms | **19 ms** |
| 接触直前の速度（最高速比） | 7 % | **最高速付近** |
| 拳の遠近（構え→伸展） | 72 → 69 px | **72 → 30 px** |
| 密着距離での拳の遠近 | 72 → 115 px | **72 → 30 px** |

> **2つの典型的な誤り。**
> ① 伸展に `easeOut` を使うと接触へ向けて減速し、当たる瞬間に拳が止まる。
>   実際の打撃は最高速度が接触の 8〜21ms 前に来る（Stanley 2018）。
> ② **自分の拳の見かけの大きさを、相手の画面上の大きさに結びつけてはいけない。**
>   自分の拳の見かけは自分の目からの距離だけで決まる。
>   結びつけると、相手が近いほど自分の拳が大きくなる。

### 手の管理

```
punchLock       = Clock.game + travel          // 体幹は着弾まで塞がる
handReady[side] = Clock.game + travel + recover × 0.55
```

- **飛行中の拳を次の入力で上書きしない。** 上書きすると拳が空中で消える
  （6回押して着弾3発になっていた）。
- **押した手が塞がっていたら、空いている方の手で打つ。** 拳は左右交互に出るもので、
  塞がった手を押して無反応になるのは操作として誤り。
- それでも出せないときは入力を **220ms 保持**し、空いた瞬間に出す（1-2が繋がるように）。
  同時に腕を締めて「今は打てない」を返す。無反応が一番よくない。

## 9. 距離・体力・金網

| 値 | 距離 | そこで出る技 |
|---:|---|---|
| 0 | 遠距離 | 前蹴り / ローキック / ミドル / ハイ |
| 1 | 打撃距離 | ジャブ / ストレート / フック / アッパー |
| 2 | 密着距離 | ショートフック / 肘 / 膝 |

移動は `STEP_MS = 300ms`（PERFECT後は240ms）、スタミナ −4。
移動中の被弾は **×1.25**。相手のスタミナが20未満なら被ダメージ ×0.8。

### プレイヤー側の技割り当て

| 入力 | 遠距離 | 打撃距離 | 密着距離 |
|---|---|---|---|
| 左タップ | 前蹴り | 左ジャブ | 左ショートフック |
| 右タップ | ローキック | 右ストレート | 右肘 |
| 内へスライド | ミドルキック | 左フック | 膝 |
| 上へスライド | ハイキック | 右アッパー | 膝 |
| 外へスライド | スリップ / 回り込み（攻撃が来ていなければ角度取り） |||
| 両指 上/下/中央/長押し | 前進 / 後退 / タックル / スプロール |||

### 金網

後退できない位置で下がろうとすると `cage` が増える（最大2）。
強打（10以上）を受けると30%で1段階後退し、下がれなければ金網圧力になる。
PERFECT回避で1つ減らせる（回り込み）。

## 10. 技データ

両者ともオーソドックス（左構え）。
**左＝リード**は肩が既に前にあるので溜めがほとんど無く、速いが軽い。
**右＝リア**は肩の溜め・腰の回転・後ろ足の返りが出るので読めるが重い。
`from` は一人称で見た飛来方向（−1＝画面左＝相手の右手）。
`read` は読みやすさ＝主観時間の長さと深さを決める。

| 技 | dmg | tell | impact | recover | from | read | 有効な防御 | 危険な対応 |

技を単発で選ばない。**パターン（連係）を選び、その中を進む。**

### 癖を読む（第4の柱）

```
noteHabit: 対応するたび h[choice] += 1、他は全て ×0.72   // 古い癖は薄れる
dominantHabit: 合計 2.4 以上 かつ 最頻が 55% 以上 のときだけ返す
```

**ただし予告を 1.45 倍に伸ばす。**
「読まれた」ことが分かり、かつ対応できる——これがストレスにならない条件。
入ったときだけ「読まれた」と告げる。

**目線**：攻撃方向のヒントとして目線が動くが、選手ごとに正直さが違う（`gazeTruth`）。
アラタ0.85、ゴウ0.52。嘘のときは逆方向を見る。

## 13. 音響

音源ファイルは持たない。すべてノイズとオシレータの合成。
**主観時間に入ると master に挿した低域通過フィルタが閉じる**
——「世界が遅くなる」を耳で成立させているのはこれ。

```
lp.frequency = lerp(18000, 380, (1 − Clock.scale) / 0.8)
```

| 層 | 音 | 役割 |
|---|---|---|
| 基本拍 | 足音（強／弱） | リズムの土台 |
| 裏拍 | 呼吸（吸気／呼気） | 疲労で変化。**攻撃前の吸気が予告になる** |
| 打撃 | ノイズ＋低音 | 拍へ着地させる |
| 主観時間 | 突入音（抜ける空気＋沈むサブ）/ 復帰音 | 耳ではっきり分かること |
| 見切り | PERFECT / GOOD / LATE で別の音程 | 成否を耳で返す |
| 環境 | 観客・金網・心音 | 優勢劣勢とHPで増減 |

> **iOS では WebAudio だけの出力が消音スイッチで丸ごと消える。**
> `navigator.audioSession.type = 'playback'`（Safari 16.4+）を宣言すること。
> 宣言できない端末向けに、0.05秒の無音WAVを `<audio loop>` で再生して
> メディア再生セッションを起こす保険も入れる。
> これが無いと iPhone で全SEが無音になる。詳細は `DEVICE.md`。

## 14. 触覚

**Web版では未達。ネイティブで必ず実装する。**
iOS Safari に Vibration API は存在せず、代替（switch属性の切替触覚）も実機で発火しなかった。
**これは Web の制約であって製品の制約ではない。**

設計表は `DEVICE.md` に記載。要点のみ：

- **鋭さ（sharpness）で「何が起きたか」を分ける。** 打撃は鋭く、被弾は鈍い。
  強弱だけでは区別がつかない。
- **予備動作と溜めは continuous でしか表現できない。** 単発の振動では
  「気配」も「溜まっていく」も作れない。これがネイティブにする最大の理由。
- **見える前に感じる。** 予備動作の触覚は視覚より先に出す。

呼び出し地点（`haptic('touch')` 等）はコード内の正しい場所に既にある。
移植時は `Haptic.fire()` の中身を差し替える。

## 15. 記録と分析

プレイの全イベントを localStorage に記録し、ゲーム内の記録画面で集計する。
**体感の議論を推測でしないための装置。**
仕様を変えたら `REC_V` を上げて旧データと混ぜない（現在 3）。

| イベント | 記録する内容 |
|---|---|
| `atk` | 技・予告長・接触時刻・前の着弾からの間隔・癖読みか |
| `read` | 判定・**反応時間（実時間）**・技・山を張ったか |
| `choice` | 選択・判定・**スロー窓のうち何割を使ったか** |
| `resolve` | 選択・判定・**殴られた理由**・被弾量・捌けたか・有利 |
| `swing` | 技・**溜めの深さ (0–100)**・手・ジェスチャー |
| `press` | 帯・手・**攻撃が無いのに押したか** |
| `gap` / `combo` / `reversal` / `slowin` / `noread` | 間隔・連打数・返し・減速・過剰反応 |

集計は「見切り」「選択と結果」「殴られた理由」「間と入力」「技ごと」「各戦」の6区分で出す。
**殴られた理由**（ガードを離した / 逆の手で受けた / この技に効かない対応 /
タイミング外れ / 相打ち …）が最も改善に効く。

> 書き出しは**選択できるテキストエリア**で行う。
> アーティファクトはiframe内で動くため `navigator.clipboard` は権限が無く拒否され、
> 失敗しても何も起きず「反応しない」に見える。

## 16. 人間のタイミング

判定の基準はすべてここから引く。**推測した数字を判定に入れない。**

| 定数 | 値 | 出典 |
|---|---:|---|
| `SRT_MEAN` | 231 ms | 単純反応時間の中央値（視覚） |
| `SRT_FAST` | 190 ms | 速い層の単純反応時間 |
| `DEVICE` | 70 ms | 端末遅延。iPhone 12 の touch-to-photon 実測 78ms（960fps撮影） |
| `HICK_A` / `HICK_B` | 200 / 150 | 選択反応 RT = a + b·log₂(n+1)。Hick (1952)、Proctor & Schneider (2018) |

```
REACT_FLOOR = SRT_FAST + DEVICE                  = 260 ms
CHOICE_NEED = HICK_A + HICK_B·log₂(6+1) + DEVICE = 691 ms
GAP_MIN     = CHOICE_NEED × 1.3                  = 898 ms
```

- **REACT_FLOOR** — 誰にも詰められない時間。判定の起点。
- **CHOICE_NEED** — 主観時間の中で6択から選ぶのに要る実時間。スロー窓の長さの根拠。
- **GAP_MIN** — 着弾から次の予備動作までの最低間隔。
  「結果を見る → 選択反応を1周する → 構え直す」に要る時間。

打撃の物理側：肘角度はジャブ 112.9° / クロス 116.9° / フック 100.1°（Dinu & Louis 2020）、
チャンバーは 50〜70°（Joch 1981）、**最高速度は接触の 8〜21ms 前**（Stanley 2018）。

詳細と変更手順は `TIMING.md`。

## 17. 検証手順

体感に関わる変更を入れたら、**触ってもらう前に測る**。
headless Chromium（Playwright）でゲームを起動し、内部状態を直接読む。

| 測るもの | 方法 | 合格基準 |
|---|---|---|
| 押してから拳が動くまで | `__noGL=1` で2D経路にし、rAFごとに `Arms.R` を記録 | ≤ 1フレーム（20ms） |
| 押した時間ごとの打撃の有無 | 60/110/170/220/300/450ms 押して `p.action` を見る | すべてで出ること |
| 拳の遠近 | 伸展中の `Arms.R.r` の最小値 | 構えの 60% 未満 |
| 溜めの効果 | 溜め0と満で与ダメージ・到達時間を比較 | 差が出ること |
| 音が実際に出ているか | `AnalyserNode` で master のピークを実測 | > 1% |
| 局面の到達可能性 | 12シチュエーションをボットで通す | 11/12 CLEAR（S09は既知） |
| UI導線 | 進捗ゼロから一覧→ブリーフ→開始を12局面 | 全通過 |
| 安定性 | 3D有効で40秒の連続プレイ | 例外ゼロ |
| PERFECT の到達可能性 | 全技について `perfW` と `REACT_FLOOR` を突き合わせる | 要求が人間の下限を下回らないこと |

> **ソフトウェアGL（SwiftShader）では 15〜18fps しか出ない。**
> 入力遅延をこの経路で測ると、フレーム律速の数字を実装の遅延と取り違える。
> 遅延計測は必ず `__noGL=1` で行うこと。
